# 成长性机制：这个仓库如何随使用变强

本仓库不是静态文档，是**实战沉淀系统**。每次真实作图产生的配方、教训、
数据集形态，按下面的流程沉淀回来，仓库随使用单调变强。

## 沉淀通道（三个）

### 1. 配方（recipes/）——「这次怎么画成的」

触发：某次作图摸索出可复现的画法（如新的面板类型、新的软件管线绕行）。

```
skills/<name>/recipes/YYYY-MM-DD-<slug>.md
```

内容：输入 schema → 关键代码 → 产出规格 → 过检证据（四查结果）。
验收：复跑一次通过（一键脚本或精确步骤）才可入库，禁止"应该能跑"。

### 2. 教训（lessons）——「这次错在哪、规则改了什么」

触发：返工/审稿意见/视觉审计抓到缺陷。

流程：错误模式 ≤8 字 → 对应 SKILL.md 的「教训集/硬规则」加一行 →
能写成断言/检查项的必须写成 CODE 形态（checkpoint 命令或审计规则），
写不成的只记 lessons 不改正文（防规则通胀）。

```
skills/<name>/lessons/YYYY-MM-DD-<slug>.md   # 完整案例
skills/<name>/SKILL.md                        # ≤1 行规则增量
```

### 3. 数据集形态（datasets/）——「这类数据长什么样」

新数据形态首次出现 → `datasets/DATASET_INDEX.md` 注册 +
`domains/*/PROFILE.md` 补字段约定（见该文件纪律节）。

## 版本与变更

- SKILL.md 头部 frontmatter 带 `version`；行为变更（规则增删）+0.1，
  破坏性重写 +1.0
- 所有沉淀进 `CHANGELOG.md`（日期 + 通道 + 一句话）
- 领域适配层（domains/）与 skill 主体分离：领域增量不污染通用规则

## 质量闸门

- 新配方必须带过检证据（四查/评分环输出）
- 规则增量优先 CODE 形态（断言/检查项），DOC 形态需说明为何无法 CODE
- 清洗外部引入内容时：方法论 attribution 保留一行（诚实边界），
  本机路径/私有项目引用一律泛化
